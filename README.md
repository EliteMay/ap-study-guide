## 現在の評価

Webアプリとしての基盤は利用できますが、**AP教材としては完成扱いにしません**。

現在公開中の6教材には合計1422語がありますが、語数は完成度の指標にしません。既存データには次の課題があります。

- 詳細解説のテンプレート比率が高い。
- アルゴリズム・システム開発・プロジェクト管理は詳細の多くを共通生成している。
- 既存6分野だけではAP全範囲をカバーしていない。
- 分野の境界が曖昧で、RFP・SLA・DNSなど重複/誤配置候補がある。
- ネットワークのようにカテゴリ件数を揃えたデータがあり、試験重要度より語数が先に立っている。
- 現在のテストは用語と定義の対応確認が中心で、計算・図・SQL・擬似言語・ケース問題を十分測れない。

## 今後の教材設計

全内容を同じ「単語カード」に押し込めません。

内容に応じて教材形式を分けます。

- 用語・概念: 短い定義、仕組み、比較、誤解しやすい点
- 計算: 公式、途中式、例題、類題
- 擬似言語/コード: 1行ずつの実行トレース
- SQL/正規化: 入力データ、操作、結果
- 図: ER図、UML、ネットワーク構成図
- ケース: 問題文から根拠を抜き出して判断する問題
- 法務: 適用場面と似た制度の比較
- 過去問: どの知識をどう適用したかまで逆算

## 改修順序

1. **ジャンル設計を公式シラバス基準へ変更** ← 現在ここ

## 完成条件

「ページが開く」「語数が多い」だけでは完成扱いにしません。

- IPAの対象シラバス全範囲を追跡できる
- 各学習項目に適切な教材形式がある
- テンプレ文章で水増ししていない
- 必要な計算・図・コード・ケース演習がある
- 過去問へ知識がつながる
- 理解度を問題結果から確認できる
- CIとPagesビルドが通る

ここまで満たして初めて教材として完成扱いにします。

## 現在の評価

Webアプリとしての基盤は利用できますが、**AP教材としては完成扱いにしません**。

現在公開中の6教材には合計1422語がありますが、語数は完成度の指標にしません。既存データには次の課題があります。

- 詳細解説のテンプレート比率が高い。
- アルゴリズム・システム開発・プロジェクト管理は詳細の多くを共通生成している。
- 既存6分野だけではAP全範囲をカバーしていない。
- 分野の境界が曖昧で、RFP・SLA・DNSなど重複/誤配置候補がある。
- ネットワークのようにカテゴリ件数を揃えたデータがあり、試験重要度より語数が先に立っている。
- 現在のテストは用語と定義の対応確認が中心で、計算・図・SQL・擬似言語・ケース問題を十分測れない。

## 教材形式

全内容を同じ「単語カード」に押し込みません。

内容に応じて教材形式を分けます。

- 用語・概念: 短い定義、仕組み、比較、誤解しやすい点
- 計算: 公式、途中式、例題、類題
- 擬似言語/コード: 1行ずつの実行トレース
- SQL/正規化: 入力データ、操作、結果
- 図: ER図、UML、ネットワーク構成図
- ケース: 問題文から根拠を抜き出して判断する問題
- 法務: 適用場面と似た制度の比較
- 過去問: どの知識をどう適用したかまで逆算

## 構造化Lesson

テンプレ詳細から脱却するため、用語カードとは別に構造化教材を追加しています。

- 共通画面: `html/lesson.html`
- renderer: `js/lesson.js`
- style: `css/lesson.css`
- index: `json/lessons/lesson-index.json`
- 個別教材: `json/lessons/<unit>/...json`

Lesson JSONは、文章だけでなく比較表・コード・実行トレース表・手順・失点例・確認問題を持てます。

### 最初の個別教材

`ALG-01 アルゴリズムの表現と擬似言語トレース`

URL:

実装済み:

## アルゴリズム65語監査

全65語をIPA中分類2と照合し、次の判定を完了しました。

監査データ:

`json/curriculum/audits/algorithm-audit.json`

| 判定 | 件数 |
|---|---:|
| 主要教材として残す | 31 |
| 補助として残す | 5 |
| 上位Lessonへ統合 | 25 |
| 別学習ユニットを主教材にする | 4 |
| 即削除 | 0 |

即削除0は全語が必要という意味ではありません。既存IDとlocalStorage進捗を壊さず、Lessonへの移行後に単独カード表示を整理するためです。

現在の65語は、IPA中分類2のうち「データ構造」「アルゴリズム」に偏っています。特に不足しているのは「プログラミング」「プログラム言語」「その他の言語」です。

6. 最近の過去問を複数分野へ追加
7. 用語4択中心のテストを、本番型演習へ拡張

## 完成条件

「ページが開く」「語数が多い」だけでは完成扱いにしません。

- IPAの対象シラバス全範囲を追跡できる
- 各学習項目に適切な教材形式がある
- テンプレ文章で水増ししていない
- 必要な計算・図・コード・ケース演習がある
- 過去問へ知識がつながる
- 理解度を問題結果から確認できる
- CIとPagesビルドが通る

ここまで満たして初めて教材として完成扱いにします。

## 2. 教材監査で確認した問題

ユーザー指摘:

- 単語解説がテンプレ6割程度に見える。
- 現在のジャンル分けが学習上妥当か疑問。

確認結果:

### テンプレ詳細

`js/term-page.js` の `generatedDetail()` により、アルゴリズム・システム開発・プロジェクト管理の212語は共通パターンで長文詳細を生成している。

セキュリティ・ネットワーク・DBの個別詳細JSONにも同じ文章構造の繰返しが多い。

### AP全範囲ではない

IPA「応用情報技術者試験 シラバス Ver.7.2」は9大分類・23中分類。

旧6教材だけでは、基礎理論、コンピュータシステム、UI/情報メディア、サービス管理/監査、戦略、経営、法務などが不足。

### 分類混在

- Security側にネットワーク/DNSが大量にあり、Network側と重複。
- SystemにRFP/SLAなど誤配置候補。
- Managementにサービス管理が混在。
- Networkは12カテゴリ×40語で、必要性より件数設計が先行した可能性が高い。

### 用語カード偏重

APには計算、SQL、正規化、擬似言語、図、ケース判断などが必要だが、旧設計はほぼ全てを用語カードへ押し込んでいた。

### 現行テストの限界

`html/test.html` は用語→定義 / 定義→用語が中心。用語理解チェックとして残すが、本番力測定とは扱わない。

これは全語を最終的に独立表示する意味ではなく、既存IDと進捗を壊さずLessonへ移行するため。

主な整理方針:

- O(1)〜O(n²) → 1つの計算量Lessonで比較。

- 再帰呼出し/基底条件 → 再帰コードトレースへ統合。
- AND/OR/XOR/ビットシフト → 基礎理論を主教材にする移動候補。

### ALG-02 実装済み

教材:

`json/lessons/algorithm/alg-02-complexity.json`

タイトル:

**ALG-02 計算量とオーダの読み方**

置換対象:

- term-alg-004 計算量
- term-alg-005 時間計算量
- term-alg-006 空間計算量
- term-alg-007 オーダ記法
- term-alg-008 O(1)
- term-alg-009 O(log n)
- term-alg-010 O(n)
- term-alg-011 O(n log n)
- term-alg-012 O(n²)

9枚の似た長文カードとして覚えない構成へ変更した。

内容:

- 計算量は実測秒数ではなく入力サイズに対する増え方を見ること
- n=10 / 100 / 1000で代表5オーダを比較
- O(1)のコード例と処理回数
- 1重ループからO(n)を求める
- 2重ループの外側×内側からO(n²)を求める
- 内側が固定回数なら2重ループでもO(n)になる例
- 半分ずつ縮む処理からO(log n)を理解
- O(n log n)を「n個×log n段」で理解
- 3n+20、5n²+2n+100などから支配項を選ぶ
- 時間計算量と空間計算量の比較
- コードからオーダを読む5段階手順
- 典型的な失点
- 7問の確認問題

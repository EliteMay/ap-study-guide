# 2026-08-29 教材監査

ユーザーから次の問題提起:

- 単語解説がテンプレ6割程度に見える。
- 現在のジャンル分けが本当に学習に適しているか分からない。
- サイトを完成品ではなく、問題の多い教材として厳しく見直したい。

## 確認した問題

### 1. テンプレ詳細

`js/term-page.js` の `generatedDetail()` により、アルゴリズム・システム開発・プロジェクト管理の212語は、軽量定義とカテゴリ説明から共通パターンの詳細を生成している。

既存のセキュリティ・ネットワーク・DBの個別詳細JSONにも、同じ文章構造の繰り返しが多数ある。

結論:

**文章量は多いが、用語固有の学習情報が薄いカードがある。**

### 2. AP全範囲ではない

IPA「応用情報技術者試験（レベル3）シラバス Ver.7.2」を基準に確認。

公式範囲は:

- 3系統
- 9大分類
- 23中分類

現在の6教材だけでは、基礎理論、コンピュータシステム、UI/情報メディア、サービスマネジメント/監査、戦略、経営、法務などが不足している。

### 3. 分類の基準が混在

例:

- セキュリティ内にネットワーク基礎・DNSが大量にある一方、ネットワーク教材も別に存在。
- システム開発にRFPやSLAなど別分類へ移すべき候補がある。
- プロジェクト管理にサービスマネジメントが混在。
- ネットワークは12カテゴリが40語ずつで、試験上の必要性より件数設計が先に立った可能性が高い。

### 4. 全分野を用語カードへ寄せすぎ

APでは用語以外に、次の能力が必要。

- 計算
- 擬似言語トレース
- SQL
- 正規化
- ER/UML/ネットワーク図
- ケース判断
- 法務の適用判断

現行データモデルではこれらを十分扱えない。

### 5. 現行テストの限界

現行 `html/test.html` は主に「用語→定義」「定義→用語」の4択。

用語理解の確認には使えるが、本番力を測るテストとは扱わない。

# 2026-08-29 教材再設計 Phase 2-1: アルゴリズム65語監査

## 目的

最初の全件監査対象としてアルゴリズム65語を選び、今後1422語全体へ使う監査ルールを確立する。

既存用語をいきなり削除するとlocalStorageの進捗・復習リンクを壊すため、**監査段階ではIDを維持し、最終UIで統合する候補を判定する**方式にした。

## 公式範囲との比較

IPA中分類2は「アルゴリズムとプログラミング」で、小分類は次の5つ。

1. データ構造
2. アルゴリズム
3. プログラミング
4. プログラム言語
5. その他の言語

既存65語はデータ構造と代表アルゴリズムには比較的多く触れているが、プログラミング・プログラム言語・その他の言語が大幅に不足している。

## 全65語の判定ファイル

追加:

`json/curriculum/audits/algorithm-audit.json`

全65 IDについて次を記録。

- action
- officialArea
- priority
- contentType
- targetLesson
- note

判定結果:

| action | 件数 |
|---|---:|
| `keep-core` | 31 |
| `keep-supporting` | 5 |
| `merge-into-lesson` | 25 |
| `move-primary-unit` | 4 |
| 即削除 | 0 |

即削除0は全語を残すという意味ではない。進捗移行前にIDを消さないための判断。

## 統合候補の例

### 計算量

従来:

- O(1)
- O(log n)
- O(n)
- O(n log n)
- O(n²)

をそれぞれ独立カードとしていた。

方針:

`ALG-02 計算量とオーダの読み方` の1教材で、同じグラフ・コード例を使って比較する。

### 木

`根` / `葉` は単独長文カードではなく、木構造の1枚の図の部位名として統合する。

### グラフ

`有向グラフ` / `無向グラフ` / `重み付きグラフ` は、グラフ教材の比較要素として統合する。

### 再帰

`再帰呼出し` / `基底条件` は、再帰コードを1行ずつ追う教材へ統合する。

## 別ユニット移動候補

次の4語は主教材を `基礎理論・数学` 側へ移す候補とした。

- 論理積 AND
- 論理和 OR
- 排他的論理和 XOR
- ビットシフト

アルゴリズム/プログラミング側では削除せず、条件式・ビット操作から関連参照する。

`ビットマスク` はプログラミングでの利用形態として補助教材に残す候補。

## 15の目標教材

既存65語を最終的に15教材程度へ整理する設計を監査JSONへ追加。

例:

- `ALG-01` アルゴリズムの表現と擬似言語トレース
- `ALG-02` 計算量とオーダ
- `ALG-03` 配列・リスト
- `ALG-04` スタック・キュー
- `ALG-05` ハッシュ表
- `ALG-06` 探索
- `ALG-07` ソート比較
- `ALG-08` 再帰と問題分割
- `ALG-09` 木
- `ALG-10` グラフ・最短経路
- `ALG-11` 文字列探索
- `PROG-01` 基本制御・データ型
- `PROG-02` 関数・モジュール・引数・スコープ
- `PROG-03` プログラミング言語分類
- `PROG-04` Web・マークアップ・データ記述言語

## 不足範囲を明示

監査JSONに `missingLearningGoals` を追加。

主な高優先不足:

- 多次元/動的配列
- 循環リスト
- push/pop/enqueue/dequeue
- 完全二分木、平衡木、B木、AVL木
- 木の各走査順
- シェルソート
- ベルマンフォード法
- KMP法 / BM法
- 決定表
- 順次/選択/反復の実コード
- データ型
- 関数・引数・値渡し/参照渡し
- モジュール化
- コーディング規約
- BNF / EBNF
- プログラミング言語のパラダイム
- スコープ / ヒープ / GC

中優先範囲もIPA範囲として追跡するが、**IPAのキーワードを全部1用語1長文カードへ変換することは禁止**する方針。

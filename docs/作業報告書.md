# 今回見つかった主な問題

## 1. BuildのSingle Source of Truth不足

以前は `js/shell.js` と複数Validator / HTML / 文書へBuild値を手入力していた。

Guideの以下に該当。

- Failure F-004: Single Source of Truth不在
- Anti-pattern AP-004: Duplicated Source Data
- Maintenance: Versionを一元化

## 2. Homeの件数hardcode

Homeの初期HTMLや説明に `118 / 91 / 16 / 1,422` 等が直接書かれ、Data更新後に古い値が残る余地があった。

Guideの以下に該当。

- Failure F-013: 古いhardcodeが残る
- Anti-pattern AP-007: Magic Counts

## 3. Backup ImportのValidation不足

認識済みStorage Keyかつ値が文字列ならImport可能だったため、壊れたJSON文字列でも現在データへ上書きできる余地があった。

GuideのData / Storageにある `parse → version → migrate → normalize → validate → commit` とImport前Validationに対して不十分だった。

## 4. Import JSON由来文字列の`innerHTML`

Backup PreviewでImport JSONの `build` / `exportedAt` をHTML文字列へ組み込んでいた。

GuideのAnti-pattern AP-019「Raw innerHTML for External Data / Import JSON」に該当。

## 5. Restore途中失敗時のRollback不足

複数Keyの`localStorage.setItem`途中で失敗した場合、一部だけ新しい状態になる可能性があった。

## 6. HomeのError State不足

教材Loader失敗時はConsole Errorだけで、画面が「確認中」のまま残る可能性があった。

GuideのUI原則 `Loading / Empty / Error / Success` とAP-012 No Error Stateに対して不足。

## 7. Home FinderのListener重複余地

`init()`はStorage / Lesson Progress更新でも再実行されるが、Finder Listenerも毎回追加していた。

長時間利用時の重複Eventを避けるため修正対象とした。

## 8. Browser Smokeの回帰範囲不足

Static / Browser Smokeは存在したが、Guideで過去事故として重視されている320px横overflowとBackup Import破損を直接検査していなかった。

# 実装した修正

## 1. Project Metadataを正本化

新規:

`json/project-meta.json`

正本とした情報:

- App名
- Build
- Web Project Guide Repository / Version
- Project Profile
- Deployment target
- Backup Schema Version

当時Build:

**`2026.08.30-r18`**

`js/shell.js` から固定 `const BUILD` を削除し、`project-meta.json` を読み込んでSidebar / Mobile / Footerへ反映する。

Metadataが読めなくてもNavigation自体は利用可能にする。

## 2. Home件数をData由来へ変更

変更:

- `index.html`
- `js/home.js`

初期HTMLは固定教材件数を持たず、以下をLoader完了後の実Dataから描画する。

- Lesson数
- Practice数
- Case数
- 各理解済み数

Homeの主要カード説明から変化しやすい教材件数を削除した。

## 3. Home Error / Empty State

`js/home.js` に `renderLoadError()` を追加。

Loader失敗時:

- `LOAD ERROR`
- 「教材データを読み込めませんでした」
- 再読込導線
- Unit GridのError表示

を表示する。

主要8Action CardはData Loader失敗時でも残す。

Unit Dataが空の場合もEmpty Stateを表示する。

## 4. Finder Listenerを一度だけ登録

`finderBound` と `finderCatalog` を分離。

学習状態の再集計では検索Catalogだけ更新し、Input / Keydown / Document click Listenerを重複登録しない。

## 5. Backup ImportをKeyごとにValidation

変更:

- `js/data-tools.js`
- `html/data.html`

Import時に以下を確認する。

1. JSON Parse
2. App
3. Backup Schema Version
4. `storage` object
5. 認識済みKey
6. Keyごとの保存形式
7. Preview
8. User Confirm
9. Restore

最低形式:

- Theme: `light` / `dark`
- Lesson / Practice / Case / Active Mock: JSON object
- Mock History / Bookmark / Recent / Legacy Test / Legacy checked: JSON array

認識済みKeyに壊れたJSONが1件でも含まれる場合、Restore Buttonを有効化しない。

## 6. Import PreviewをSafe DOM化

以前の`innerHTML`を廃止。

`replaceChildren()` / `document.createElement()` / `textContent`でPreviewを組み立てる。

Import JSON内のHTML文字列をMarkupとして実行しない。

`#data-import-preview`へ `aria-live="polite"` を追加した。

## 7. Restore前Backup + Rollback

現在の学習Dataがある状態でRestoreを実行する場合、先に:

`ap-study-before-restore-YYYYMMDD.json`

を自動Downloadする。

Restore開始時に上書き対象の現在値をMemoryへ退避する。

`localStorage.setItem` が途中失敗した場合、退避値を使って可能な範囲で元状態へRollbackする。

## 8. Browser Smoke強化

`tests/e2e-smoke.mjs`

追加:

- Project MetadataからBuildが表示されること
- Homeの件数がLoading状態から実Dataへ変わること
- 320px Homeでページ全体の横overflowなし
- 320px Glossaryでページ全体の横overflowなし
- 壊れた認識済みStorage JSONをImport拒否
- 悪意あるHTML文字列をBackup Metadataへ入れてもDOM化・実行されない
- Valid Backupを実際にRestoreできる
- Restore前Backup経路を通る

既存のHome / Glossary / Unit / Lesson / Practice / Case / Mobile Drawer確認も維持する。

## 9. ValidatorをSource of Truthへ追従

`tests/validate-runtime-quality.mjs` が `json/project-meta.json` を正本として以下を検証する。

- Build形式
- Guide Repository / Version
- Project Profile
- GitHub Pages target
- Backup Schema
- Shellへ固定BUILD再混入がないこと
- Homeの旧Magic Count再混入がないこと
- Home Error State / Dynamic Count
- Safe Backup Import / Rollback
- Import Previewのraw innerHTML再混入禁止

## 10. Documentation整理

`README.md` を現在仕様中心へ再構成した。

長いVersion履歴はREADMEから外し、変更履歴は本作業報告へ記録する。

`docs/仕様書.md` には現在のSource of Truth / Home State / Backup Pipeline / Testing基準を反映した。

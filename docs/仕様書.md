# AP Study Notes 仕様書

## 1. 概要

応用情報技術者試験（AP）の学習用静的Webサイトです。

GitHubリポジトリ `EliteMay/ap-study-notes` を正本とし、HTML/CSS/JavaScript/JSON/PDFで構成します。現在の構成は固定ではなく、学習効果・操作性・軽量性・保守性が上がるなら再設計して構いません。

## 3. 共通用語ページ

`security.html`、`network.html`、`database.html` は共通エンジンを利用します。

### 共通実装

- `js/term-page.js`
- `css/term-page.css`

### ページ固有設定

各HTMLは `window.TERM_PAGE_CONFIG` で以下を指定します。

- 表示名
- 用語マニフェスト
- 詳細解説マニフェスト
- localStorageキー
- フォールバックID接頭辞
- ルート相対パス

### 共通機能

- マニフェスト読み込み
- カテゴリ別JSON読み込み
- 用語一覧生成
- カテゴリ目次生成
- リアルタイム検索
- カテゴリフィルタ
- 詳細解説の遅延描画
- 用語間自動リンク
- URLハッシュから用語カードを開く
- 習得済みチェック
- 進捗バー
- localStorage保存
- 目次ハイライト
- 基本データ整合警告

## 4. 用語データ

### 軽量用語

保存先: `json/terms/`

```json
{
  "id": "...",
  "term": "...",
  "aliases": [],
  "category": "...",
  "definition": "..."
}
```

一覧・検索用なので長文を入れすぎないことを推奨します。

### 詳細解説

保存先: `json/details/`

主なフィールド:

- `id`
- `term`
- `category`
- `level`
- `tags`
- `beginner`
- `example`
- `examPoint`
- `trap`
- `deepDive`
- `relatedConcepts`
- `commonMistakes`
- `afternoonUse`
- `howToRemember`

用語JSONと `id`、`term`、`category` を対応させます。

## 6. ホーム

### ファイル

- `index.html`
- `css/home.css`
- `js/home.js`

### 仕様

- 学習単元カード数をDOMから集計する。
- 公開中単元数をDOM状態から集計する。
- セキュリティ/ネットワーク/DBの総語数は各マニフェストから取得する。
- 習得済み数は各localStorageキーから取得する。
- 過去問数は `security-past-index.json` から取得する。

件数ごとに個別の同期関数を増やさず、設定配列から共通処理します。

## 7. 進捗保存

現在はlocalStorageを利用します。

| 分野 | キー |
|---|---|
| 情報セキュリティ | `security-terms-checked` |
| ネットワーク | `network-terms-checked` |
| データベース | `database-terms-checked` |

用語ページ読み込み時に、現行用語IDに存在しない古い進捗IDは削除します。

キーや用語IDを変更する場合は、既存進捗を残す必要があるか判断し、必要なら移行処理を入れます。

## 8. セキュリティ過去問

### 保存場所

- 索引: `security-past-index.json`
- 問題文: `json/past-problems/`
- 解説: `json/past/`
- PDF: `sources/`

### 重要対応

索引側:

- `file`
- `problemFile`
- `sourcePdf`

解説側:

- `sourceProblemFile`
- `sourcePdf`
- `sections`

問題文側:

- `problem.questions[].label`
- `problem.questions[].targets`

解説 `sections[].answerTargets` と問題文 `questions[].targets` は、同じ設問ラベル同士で一致させます。

## 9. テスト

現在の `html/test.html` は古い用語配列と手作りAP本番風問題を同じJavaScript内に保持しています。

これは現在の正式な用語JSONと二重管理になるため、将来の構成は次を推奨します。

```text
最新用語JSON ─┐
               ├─ test engine ─ 選択式/復習問題
手作り問題JSON ┘
```

通常の用語問題は正式JSONから生成し、品質を調整した手作り問題だけ専用JSONとして保持します。

## 10. 品質チェック

`tools/check-json.html`

### 用語系

- 3分野すべてを検査
- ファイルごとのcount
- manifest総数
- 用語ID重複
- term重複
- 詳細ID重複
- 用語/詳細のID対応
- term一致
- category一致

### 過去問

- 索引の解説ファイル読み込み
- `problemFile` 読み込み
- `sourceProblemFile` 対応
- `sourcePdf` パス情報対応
- `sections`
- `answerTargets`
- `expectedAnswers`
- 問題文 `targets` と解説 `answerTargets` の一致
- 問題文側の設問に解説漏れがないか

基本完了条件は `ERROR 0` です。

## 13. 完了前チェック

- JSON読み込み失敗がない
- `tools/check-json.html` でERROR 0
- 必要ファイルの参照切れがない
- JS構文エラーがない
- 主要ページの検索・絞り込み・詳細表示が動く
- 習得チェックが保持される
- スマホ幅で致命的にはみ出さない
- 変更内容を `docs/作業報告書.md` に記録する

実際に確認できなかった項目は、確認済みとして記録しません。

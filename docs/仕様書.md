# AP Study Notes 仕様書

## 1. 位置付け

応用情報技術者試験（AP）の個人学習用静的Webアプリ。

- 正本: GitHub `EliteMay/ap-study-notes`
- 主利用環境: GitHub Pages
- 構成: HTML / CSS / JavaScript / JSON / PDF
- BUILD: `2026.08.30-r6`
- 状態: **機能基盤は利用可能 / 教材内容は再設計中**

ページ数・用語数だけでは教材完成としない。

## 2. 目的と優先順位

AP合格に必要な知識を、単語暗記だけでなく計算・図・コード・SQL・通信フロー・ケース問題まで含めて理解し、問題へ適用できる状態にする。

優先順位:

1. 操作性
2. 分かりやすさ
3. 軽量性
4. 保守性
5. 見た目

## 3. 崩してはいけない仕様

- 既存用語IDと進捗対応を不用意に壊さない。
- localStorageキー変更時は移行処理を用意する。
- 過去問PDF / 問題JSON / 解説JSONの対応を壊さない。
- GitHub Pagesの相対パスを壊さない。
- 秘密情報/APIキーを公開リポジトリへ置かない。
- 監査前の大量削除・大量ID変更をしない。
- 旧用語の移行完了とシラバス範囲の最終完成を混同しない。

### Network教材の方針

- OSIは層名暗記だけでなくカプセル化を追う。
- IPv4はCIDR・network/broadcast/host範囲を実計算する。
- VLAN/STPは構成図でbroadcast範囲とL2 loopを判断する。
- routingはlongest prefix matchを実際のroute tableで解く。
- TCPはSYN/ACK、sequence、window、再送を時系列で追う。
- DNS/HTTP/mailはapplication単語を通信フローへ統合する。
- 運用は `link → IP → gateway → DNS → port → application` の切り分け順を使う。
- cloudは製品名暗記ではなくroute/address/security境界へ抽象化する。

### `legacyTermRanges`

Networkの連続した旧IDは以下のように範囲で保持できる。

```json
{
  "legacyTermRanges": [
    {"prefix":"net-dns-","from":1,"to":40}
  ]
}
```

`tests/validate-audits.mjs` がゼロ埋め3桁IDへ展開して検証する。

Securityと重なるTLS、DNSSEC、FW、IDS/IPS/WAF、SPF/DKIM/DMARC、ZTNA等はSecurity 501語監査前に過剰移動せずNetwork文脈でも保持する。

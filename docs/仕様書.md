# AP Study Notes 仕様書

## 1. 概要

このフォルダは、応用情報技術者試験（AP）の学習用静的Webサイトです。HTML、CSS、JavaScript、JSON、PDFで構成され、ブラウザで各単元の用語学習、習得チェック、検索、過去問解説、ランダムテストを行います。

中心となる設計は「表示はHTML/JavaScript、学習データはJSONに分離する」ことです。特に情報セキュリティ分野は、用語501件、詳細解説501件、過去問解説7件をJSONから読み込むデータ駆動型の構成になっています。ネットワーク分野も、用語480件、詳細解説480件をJSONから読み込む公開中の単元です。

仕様の優先順位は `README.md` が最上位、`docs/仕様書.md` が補助資料です。両者に矛盾がある場合は `README.md` を優先し、`docs/仕様書.md` を `README.md` に合わせて更新します。

## 2. 想定利用者

- 応用情報技術者試験の受験者
- 情報セキュリティ、データベース、ネットワークなどの基礎を復習したい学習者
- HTML/CSS/JavaScriptの学習を兼ねて、静的サイトを拡張したい作成者

## 3. 動作環境

- ブラウザで閲覧する静的サイト
- `fetch()` でJSONを読み込むページがあるため、`file://` 直開きでは一部機能が動かない可能性があります。
- 推奨実行方法は VS Code の Live Server などでローカルHTTPサーバとして開くことです。
- 外部ライブラリやビルドツールは不要です。

## 6. 共通UI仕様

全ページ共通の見た目は `css/style.css` が担当します。

- 上部ナビゲーションで各単元へ移動できる。
- 現在ページは `.is-current` で強調する。
- 準備中ページは `.is-coming` で薄く表示する。
- ヘッダーには単元名、説明文、必要に応じて検索欄や進捗欄を表示する。
- 用語カードは `.card` を基本単位とし、習得済み状態では `.is-checked` を付ける。
- 画面幅700px以下ではナビ、カード、進捗UIを縦積みにする。

## 8. 情報セキュリティ用語画面仕様

### 主な機能

- `security-terms-manifest.json` から用語JSON一覧を読み込む。
- `security-details-manifest.json` から詳細解説JSON一覧を読み込む。

- 習得済みチェックを `localStorage` に保存する。
- ページ内目次を自動生成し、スクロール位置に応じて現在カテゴリを強調する。
- 過去問解説ストックを読み込み、関連用語へのリンクを表示する。

### 読み込み対象

| 種類 | マニフェスト | 実データ | 件数 |
|---|---|---|---:|
| 軽量用語 | `security-terms-manifest.json` | `json/terms/*.json` | 501 |

| 過去問解説 | `security-past-index.json` | `json/past/*.json` | 7 |

### 用語JSON仕様

`json/terms/*.json` は検索・一覧表示向けの軽量データです。

```json
{
  "id": "sec-001",
  "term": "情報セキュリティ",
  "aliases": ["セキュリティ"],
  "category": "セキュリティ基礎・超基礎",
  "definition": "情報を安全に扱うために、漏えい・改ざん・停止・不正利用などを防ぐ考え方と対策。"
}
```

| フィールド | 内容 |
|---|---|
| `id` | 用語の一意ID。詳細解説と対応する。 |
| `term` | 表示する用語名。 |
| `aliases` | 別名、略称、英語表記。検索対象になる。 |
| `category` | カテゴリ名。絞り込みとグルーピングに使う。 |
| `definition` | 一覧カードに出す短い説明。 |

### 詳細解説JSON仕様

`json/details/*.json` は用語カードの詳細展開用データです。

ルート構造は `meta` と `details` 配列です。各詳細解説オブジェクトの正式フィールドは以下です。

| フィールド | 内容 |
|---|---|
| `id` | 用語JSONと一致させるID。 |
| `term` | 用語名。 |
| `category` | カテゴリ名。 |
| `level` | 基礎、標準などのレベル表示。 |
| `tags` | 分類タグ。 |
| `beginner` | 初学者向け説明。 |
| `example` | 具体例。 |
| `examPoint` | 試験で問われやすい点。 |
| `trap` | ひっかけ、注意点。 |
| `deepDive` | 見出し付きの深掘り解説。 |
| `relatedConcepts` | 関連用語。 |
| `commonMistakes` | よくある誤解。 |
| `afternoonUse` | 午後問題での読み方、使い方。 |
| `howToRemember` | 覚え方。 |

`mechanism`, `afternoonPoint`, `memoryHook`, `usedInPastQuestions` は現在の正式フィールドではありません。新規追加時は、`deepDive`, `afternoonUse`, `howToRemember`, `relatedConcepts` へ整理してください。

## 9. セキュリティ過去問解説画面仕様

対象ファイル: `html/security-past.html`

### 主な機能

- `security-past-index.json` を読み込み、過去問解説ファイルを取得する。
- 用語JSONを読み込み、解説文中の用語を `html/security.html#用語ID` へ自動リンク化する。
- `html/security.html#用語ID` で開いたときは、用語JSON描画後に該当カードへスクロールし、詳細解説を自動で開く。
- 辞書に対応IDがない関連語は `href="#"` にせず、未登録の表示にする。
- 過去問を年度・回、テーマ、関連語で検索できる。
- 試験回で絞り込める。
- 各過去問カードを開閉し、設問別の答案ガイド、解説、確認チェックリスト、問題文起こし、PDFリンクを表示する。
- `answerTargets` と `expectedAnswers` を使い、設問単位の解説漏れを確認できる。

## 14. JSON品質チェック仕様

対象ファイル: `tools/check-json.html`

Live Serverで開き、ボタンを押すと以下を確認します。

- 用語IDの重複
- 用語名の重複
- セキュリティ用語とネットワーク用語の、軽量用語JSONと詳細解説JSONの件数一致
- マニフェストの件数と実データ件数の一致
- 過去問解説JSONの存在
- 問題文JSONの存在
- `sections` の有無
- `answerTargets` の有無
- `expectedAnswers` の有無

合格条件は以下です。

- 画面上の出力に `ERROR` が0件である。
- JSON読み込み失敗がない。
- 用語ID、詳細解説ID、過去問IDの重複がない。
- セキュリティ用語501件・詳細解説501件、ネットワーク用語480件・詳細解説480件が対応している。
- `security-past-index.json` の `problemFile` が実在する。
- `json/past/*.json` の `sourceProblemFile` が実在する。
- 問題文JSONの `targets` と解説JSONの `answerTargets` に不一致がない。
- ブラウザのconsoleに、JSON読み込み失敗、ID不一致、targets不一致の警告が出ていない。

`WARN` が出た場合は内容を確認し、意図した未確定メモ以外は修正します。ID不一致、ファイル不存在、targets不一致に関する警告は完了前に直します。

## 16. 保守ルール

### ネットワーク用語を追加する場合

4. `network-terms-manifest.json` と `network-details-manifest.json` の件数を更新する。

6. `docs/作業報告書.md` に確認内容、修正内容、残課題を追記する。

## 17. 解説品質の確認方針

- 用語の短い定義は `json/terms/*.json`、理解用の説明は `json/details/*.json` に分ける。
- 詳細解説は、定義だけで終わらせず「例」「試験での出方」「ひっかけ」「午後問題での使い方」を含める。
- 「万能な対策」「名前だけで判断」などの汎用表現は、対象用語に合わない場合があるため、カテゴリ単位で読み直す。
- 過去問解説は、設問ごとに `answerTargets` と `expectedAnswers` を確認し、空欄や設問の片方だけを解説して終わらないようにする。
- JSON読み込み機能はHTTPサーバ経由での閲覧を前提にしている。
- ChatGPTへ相談、整理、説明、調査だけを依頼する場合は、`docs/ai/AI最重要ルール.md` を前提に簡潔に回答させ、作業前確認表は要求しない。
- ChatGPTへ既存サイトに取り込む成果物案を依頼する場合は、対象ページ、文書、1カテゴリ、1過去問、またはID指定で範囲を絞り、作業前確認表を返させてから作成を開始する。
- ChatGPTは指定範囲の文章、JSON、HTML/CSS、README・仕様書などの改善案を作成できる。仕様解釈、複数ファイル連携、ID・リンク・索引、HTML/CSS/JavaScript、PDF照合などに不確実性がある場合だけ `Codex確認推奨` を付ける。
- ChatGPTの成果物を本番へ採用する最終判断、既存ファイルへの反映、検証、READMEとの整合確認はCodexで行う。

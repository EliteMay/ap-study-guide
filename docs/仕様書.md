# AP Study Notes 仕様書

## 1. 位置付け

応用情報技術者試験（AP）の個人学習用静的Webアプリ。

- 正本: GitHub `EliteMay/ap-study-notes`
- 主利用環境: GitHub Pages
- 構成: HTML / CSS / JavaScript / JSON / PDF
- BUILD: `2026.08.30-r7`
- 状態: **機能基盤は利用可能 / 旧教材監査完了 / シラバス不足範囲を再設計中**

ページ数・用語数だけでは教材完成としない。

## 2. 目的と優先順位

AP合格に必要な知識を、単語暗記だけでなく計算・図・コード・SQL・通信フロー・Security Caseまで含めて理解し、問題へ適用できる状態にする。

優先順位:

1. 操作性
2. 分かりやすさ
3. 軽量性
4. 保守性
5. 見た目

## 3. 崩してはいけない仕様

- 既存用語IDと進捗対応を不用意に壊さない。
- localStorageキー変更時は移行処理を用意する。
- 過去問PDF / 問題JSON / 解説JSONの対応を壊さない。
- GitHub Pagesの相対パスを壊さない。
- 秘密情報/APIキーを公開リポジトリへ置かない。
- 監査済みIDの主Lesson割当を根拠なく変更しない。
- 旧用語の監査完了とAPシラバス全範囲完成を混同しない。

## 7. `legacyTermRanges`

連続IDを大量に列挙せず範囲で保持できる。

```json
{
  "legacyTermRanges": [
    {"prefix":"net-dns-","from":1,"to":40}
  ]
}
```

CIで実IDへ展開し、未割当・重複を検出する。

Security主教材:

1. SEC-01 情報セキュリティの目的・資産・脅威・設計原則
2. SEC-02 暗号・ハッシュ・パスワード保護
3. SEC-03 PKI・証明書・TLS・鍵管理
4. SEC-04 認証・認可・MFA・SSO・ID管理
5. SEC-05 Webアプリ攻撃と安全な実装
6. SEC-06 メール認証・フィッシング・ソーシャルエンジニアリング
7. SEC-07 マルウェア・標的型攻撃・侵入後行動
8. SEC-08 認証・ネットワーク・実装への攻撃パターン
9. SEC-09 防御機構・ハードニング・アクセス制御
10. SEC-10 監視・インシデント対応・フォレンジック・復旧
11. SEC-11 ISMS・リスクアセスメント・脆弱性管理
12. SEC-12 クラウドセキュリティ・ゼロトラスト

方針:

- 純粋な通信原理はNetworkへ移す。
- Securityでは攻撃・防御上の意味を扱う。
- 攻撃は名前だけでなく「成立条件 → 観測 → 影響 → 対策」で学ぶ。
- 暗号は機密性/完全性/認証/否認防止など目的から選ぶ。
- 認証はAuthentication / Authorization / OAuth / OIDCをFlowで区別する。
- Incident Responseは検知・封じ込め・根絶・復旧・事後改善を時系列で扱う。

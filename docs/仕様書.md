# AP Study Notes 仕様書

## 1. 位置付け

応用情報技術者試験（AP）の個人学習用静的Webアプリ。

- 正本: GitHub `EliteMay/ap-study-notes`
- 主利用環境: GitHub Pages
- 構成: HTML / CSS / JavaScript / JSON / PDF
- 現在BUILD: `2026.08.29-r5`
- 状態: **機能基盤は利用可能 / 教材内容は再設計中**

従来の「6分野1422語が公開されているため完成」という判定は採用しない。

## 2. 要件定義

### 目的

APの合格に必要な知識を、単語暗記だけでなく、計算・図・コード・SQL・ケース問題まで含めて理解し、問題へ適用できるようにする。

### 使う人

個人学習者。企業向けの複雑な権限管理より、軽量性・使いやすさ・学習効率を優先する。

### 必要機能

- AP全範囲の学習マップ
- 各学習項目の教材
- 検索 / 復習 / 進捗
- 内容に応じた演習
- 過去問
- 解答履歴
- 理解度の可視化
- GitHub Pagesでの静的利用

### 保存

個人進捗はlocalStorage。教材データはJSON。

### 崩してはいけないもの

- 既存用語IDと進捗の対応を不用意に壊さない
- localStorageキーを変更する場合は移行する
- 過去問PDF / 問題文 / 解説の対応を壊さない
- GitHub Pagesの相対パスを壊さない
- APIキーや秘密情報を公開リポジトリへ置かない

### 教材としての完成条件

- 対象シラバス全範囲を追跡できる
- テンプレ文章による水増しがない
- 学習項目に合う教材形式を使う
- 計算 / 図 / コード / SQL / ケース問題が必要箇所にある
- 最近の過去問へ接続できる
- 問題結果から理解度を確認できる
- 自動検証とPagesビルドが通る

## 6. 教材データモデル方針

今後は全内容を同じdetail形式へ押し込まない。

### concept

用途: 用語・概念・比較。

必要要素例:

- 一言定義
- なぜ必要か
- 仕組み
- 似た概念との差
- 典型的な誤解
- APでの問われ方

### calculation

用途: EVM、PERT、サブネット、待ち行列、性能計算など。

必要要素例:

- 公式
- 変数の意味
- 途中式
- 例題
- 類題
- 間違えやすい符号/単位

### code-trace

用途: 擬似言語・アルゴリズム。

必要要素例:

- コード
- 初期値
- 各行実行後の変数
- 配列/スタック/キュー状態
- 最終出力

### structured-operation

用途: SQL、正規化。

必要要素例:

- 入力表
- 操作
- 中間状態
- 結果
- なぜその結果になるか

### diagram

用途: ER図、UML、ネットワーク構成図。

必要要素例:

- 図
- 見る順番
- 記号の意味
- 根拠箇所
- 読み違い例

### case

用途: セキュリティ、PM、サービス、戦略、法務等。

必要要素例:

- 状況文
- 条件
- 根拠
- 選択/記述
- 解説

# AP Study Notes 仕様書

## 1. 概要

応用情報技術者試験（AP）の個人学習用静的Webアプリ。

- 正本: GitHub `EliteMay/ap-study-notes`
- 主利用環境: GitHub Pages
- 構成: HTML / CSS / JavaScript / JSON / PDF
- BUILD: `2026.08.29-r4`
- v1.0収録用語: **1422語 / 6分野**

操作性、分かりやすさ、軽量性、保守性を優先し、現在のUI構成そのものは固定しない。

## 3. 学習フロー

1. Dashboardから単元を選ぶ、または前回の続きへ戻る。
2. 検索・カテゴリから用語を探す。
3. 定義と詳細解説を読む。
4. まだ怪しいものを `☆ 復習` へ入れる。
5. 理解できたものを `✓ 習得済み` にする。
6. 分野別 / 6分野ミックス / 復習リストでテストする。
7. 間違いだけ再テストする。
8. 情報セキュリティは午後過去問でも確認する。
9. Dashboardで進捗・直近テスト・最近見た用語を確認する。

## 7. 用語・詳細データ

軽量用語:

`json/terms/*.json`

必須に近いフィールド:

`id`, `term`, `category`, `definition`

任意:

`aliases`

### 個別詳細JSON方式

対象:

- 情報セキュリティ
- ネットワーク
- データベース

`json/details/*.json` を読み込む。

主なフィールド:

`id`, `term`, `category`, `level`, `beginner`, `example`, `examPoint`, `trap`, `deepDive`, `relatedConcepts`, `commonMistakes`, `afternoonUse`, `howToRemember`

### 共通生成詳細方式

対象:

- アルゴリズム
- システム開発
- プロジェクト管理

v1.0では `generateDetails:true` とし、軽量定義 + manifestのカテゴリ説明から共通エンジンが詳細を生成する。

個別詳細JSONを追加した場合は個別詳細を優先し、不足分だけ生成する設計へ拡張可能。

## 9. テスト

- `html/test.html`
- `css/test.css`
- `js/test.js`

出題元:

- 6分野ミックス
- 各分野
- ☆復習リスト

仕様:

- 最大100問
- 説明→用語 / 用語→説明 / ミックス
- 同カテゴリ中心 / 標準の誤答候補
- 説明文中の正解語・別名を自動マスク
- 1〜4キー回答
- Enterで次へ
- 間違い一覧
- 間違いだけ再テスト
- 辞書へ直接戻る
- テスト結果を直近30回保存

復習モードは正解対象を復習リストから選ぶが、誤答候補は全辞書を利用して難易度低下を抑える。

## 10. 情報セキュリティ過去問

- 表示: `html/security-past.html`
- ロジック: `js/past.js`
- CSS: `css/past.css`
- 索引: `security-past-index.json`
- 問題文: `json/past-problems/`
- 解説: `json/past/`
- PDF: `sources/`

解説 `sections[].answerTargets` と問題文 `questions[].targets` は同じ設問ラベルで一致させる。

表示互換:

- `studyChecklist` / `reviewChecklist`
- choices文字列 / `{key,text}`
- `answerGuide` 不足時のフォールバック

## 11. 品質保証

### CI

`.github/workflows/validate.yml`

mainへのpush / PRで:

1. `js/*.js` を `node --check`
2. `node tests/validate.mjs`

を実行する。

`tests/validate.mjs` の検査:

- 全JSON構文（UTF-8 BOMは正規化）
- 6分野manifest count
- 用語ID重複
- 必須フィールド
- category定義
- 既存3分野のterms/details対応
- セキュリティ過去問targets対応
- 主要HTMLの内部href/src参照

v1.0完成時に `Validate AP Study Notes` 成功を確認済み。

### ブラウザ検査

`tests/data-integrity.test.html`

6分野 + 過去問 + 主要ファイルをGitHub Pages / Live Server上で検査する。

`tools/check-json.html` は検査ロジックの二重管理を避けるため `tests/data-integrity.test.html` へ転送する。

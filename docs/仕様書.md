# AP Study Guide 仕様書

## 1. 位置付け

応用情報技術者試験（AP）の学習用静的Webアプリ。

- Repository: `EliteMay/ap-study-guide`
- Public: `https://elitemay.github.io/ap-study-guide/`
- 正式要件: Repository Root `REQUIREMENTS.md`
- Build / Project Profile正本: `json/project-meta.json`
- 制作Guide: `EliteMay/web-project-guide` 1.17.1
- Project Memory: `PROJECT_LEARNINGS.md`
- 基準: IPA 応用情報技術者試験 シラバス Ver.7.2
- 技術: HTML / CSS / JavaScript / JSON
- Deployment: GitHub Pages

Project Profile: `STATIC + DATA + LEARNING + TOOL + PUBLIC-CONTENT`

## 2. Product Goal

初学者が単語だけを暗記するのではなく、仕組み・理由・具体例まで理解し、問題演習と復習へつなげてAP合格水準へ近づける。

基本導線:

**Home → Lesson → 途中確認 → 末尾確認 → 関連短問 → Case / Mock → 公開公式問題 → 弱点復習**

分からない内容は横断検索からLesson・用語・短問・Unit・公開公式問題へ戻る。

## 6. Lesson

- Page: `html/lesson.html?id=<LESSON_ID>`
- Base Runtime: `js/lesson.js`
- Phase 1 Runtime: `js/lesson-phase1.js`

### 6.1 既存保存Contract

- Progress Key: `ap-study-lesson-progress-v1`
- 末尾確認問題を全問回答
- 75%以上で現行の「理解確認済み」
- 現行Runtimeでは14日後に再確認対象

Phase 2導入まで、このKeyと判定を名称変更だけの理由で変更しない。

### 6.2 Phase 1 Lesson Contract

Phase 1対象Lessonは原則として次を持つ。

- importance
- frequency
- examFocus
- prerequisiteLessons
- relatedLessons
- relatedTerms
- relatedPracticeRefs
- officialProblemRefs
- 学習目標
- 十分な本文Section
- 必要な図解 / 比較 / Trace
- よくある誤解
- inlineChecks
- 末尾確認問題

既存Lesson本文が成熟している場合は `json/phase1/index.json` からUnit単位のCompanion JSONを遅延読込してOverlayしてよい。`inlineChecks` は途中理解確認で、現行Progressには保存しない。

#### 旧Database Auditの再評価

`json/curriculum/audits/database-phase1-r30.json` で、旧 `database-audit.json` が不足扱いしていた次の8学習目標が現行本文へ反映済みであることを確認する。

1. 関係代数の選択・射影・結合 ↔ SQL
2. SQL論理評価順
3. 関数従属性からの正規化と更新/挿入/削除異常
4. ロック競合と分離レベル
5. UNDO / REDO / Checkpoint / Backup
6. Indexを選択率・複合Key・範囲検索・更新Costで判断
7. 分散Transactionの2相Commit
8. OLAPのslice / dice / drill-down / roll-upとStar Schema

Evidence LessonはDB-01〜14内に明示する。

DatabaseのCompletion Blocker:

- 公開公式問題直接Mappingが5/14
- 科目A型SQL / 設計 / Transaction / 性能問題Variationの十分性が未確認
- DB-12とSecurity、DB-13とNetwork、DB-14とData利活用/Strategyの責務Reviewが残る

このため **Database Unitは `pilot / in-progress`** とする。

## 10. Backup / Restore / Reset

- Page: `html/data.html`
- Runtime: `js/data-tools.js`

ImportはParse → App/Schema → Key → Value Validation → Preview → Confirm → Restore → Failure Rollbackの順序を維持する。

Guide 1.17.1でReset/Delete lifecycle Ruleを確認済み。r30はReset/Delete実装自体を変更しない。将来変更する場合は通常保存とは別のdestructive pathとして、対象範囲・確認・失敗時状態・post-conditionを検証する。

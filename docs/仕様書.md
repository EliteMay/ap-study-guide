# AP Study Notes 仕様書

## 1. 位置付け

応用情報技術者試験（AP）の個人学習用静的Webアプリ。

- 正本: GitHub `EliteMay/ap-study-notes`
- 主利用環境: GitHub Pages
- Build / Project Profile正本: `json/project-meta.json`
- 制作Guide: `EliteMay/web-project-guide`
- Guide採用Version: `json/project-meta.json` に記録
- 基準: IPA 応用情報技術者試験 シラバス Ver.7.2
- 技術: HTML / CSS / JavaScript / JSON / PDF
- Server必須機能・秘密情報なし

Project Profile: `STATIC + DATA + TOOL + PUBLIC-CONTENT`

## 2. 目的

1. Homeから目的をすぐ選べる。
2. 13Unitから体系的に学ぶ。
3. 構造化Lessonで仕組みを理解する。
4. 短問・長文Case・模試で取り出す。
5. 最新公開公式問題へ接続する。
6. 分からない用語は統合辞書で即時検索する。
7. 進捗Dashboardから弱点へ戻る。
8. 学習データを安全にBackup / Restoreできる。

優先順位: **操作性 → 分かりやすさ → 安定性 → 軽量性 → 保守性 → 見た目**。

## 4. Home

Page: `index.html`  
Runtime: `js/home.js`  
Style: `css/home.css` + `css/home-launch.css`

Homeの第一責務は「行動選択」。詳細Dashboardではない。

主要Action:

- Lesson
- 単語辞書
- 短問
- 長文Case
- 150分模試
- 公式公開問題
- 学習進捗
- 学習データ

`#home-quick-search` は機能名・13Unit名を候補表示し、候補にない語も `html/glossary.html?q=<QUERY>` へ送る。

教材件数はLoader成功後にDataから表示する。初期HTMLは固定件数を持たない。

### 4.1 Home状態

- Loading: 初期表示
- Success: 進捗・Unitを表示
- Empty: Unit Dataが空なら説明を表示
- Error: Loader失敗時に「教材データを読み込めませんでした」と再読込導線を表示

Loader失敗時も主要8Action Cardは利用可能とする。FinderのEvent Listenerは初回だけbindし、学習状態再集計で重複登録しない。

## 5. 統合単語辞書

Page: `html/glossary.html`  
Runtime: `js/glossary.js`  
Style: `css/glossary.css`

対象は旧6分野のTerms Manifest。

- algorithm
- database
- network
- security
- system
- management

機能:

- 全文検索
- Domain / Category / Bookmark / Checked Filter
- 60件ずつ表示
- `?q=` / `?domain=` / `?term=`
- 詳細展開
- Bookmark / Checked Toggle
- Legacy Page Direct Link

全用語を検索Indexへ載せても全Cardを一括DOM生成しない。Security / Network / DatabaseのRich Detailsは詳細を開いた時だけ読み込み、Detail Fileをmemoizeする。

旧 `security.html` / `network.html` / `database.html` / `algorithm.html` / `system.html` / `management.html` は既存URL・ID・Storage互換のため残すが、通常用語検索入口にはしない。

## 7. 構造化Lesson

Page: `html/lesson.html?id=<LESSON_ID>`  
Loader: `js/lesson-data.js`

Section type:

- text
- comparison
- diagram
- code-trace
- worked-example
- steps
- mistakes

進捗: `ap-study-lesson-progress-v1`

確認問題全回答かつ75%以上で理解確認済み。

Lesson末尾の総合演習は `js/lesson-practice.js` がPractice Manifestを読み、現在Lessonを直接参照する短問へ接続する。Data異常や将来の未対応Lessonが生じてもUnit短問 / Caseへ戻れるFallbackを維持する。

## 8. 短問総合演習

- Page: `html/practice.html`
- Runtime Manifest: `json/practice/practice-index.json`
- Loader: `js/practice-data.js`
- 履歴: `ap-study-practice-history-v1`
- Choice / Written
- Writtenは最低文字数を満たすまでModel Answerを開けない

### 8.1 Lesson直接Coverage

全118 LessonがPractice Bank内の少なくとも1問から直接参照されることを必須とする。

`json/practice/ap-lesson-coverage-v1.json` は、既存Bankだけでは直接参照されなかったLessonを **1 Lesson = 1問** で補う。Coverageだけを増やす目的で複数Lessonを無関係な1問へまとめない。

現在の短問はManifest集計で139問。UIはこの値を固定表示せずRuntime Dataから算出する。

Coverage追加Bankの4択には `mockEligible:false` を付ける。これは「短問として使わない」という意味ではなく、150分模試の既存科目A Poolへ追加分を自動混入させないための属性である。

## 9. 長文Case

- Page: `html/cases.html`
- Runtime Manifest: `json/cases/case-index.json`
- 履歴: `ap-study-case-history-v1`
- 記述回答後にModel Answerと自己採点を行う

## 10. 150分オリジナル模試

Page: `html/mock.html`

科目A / 科目Bの公開仕様を参考にした独自教材。

科目AのPractice由来問題は `type === 'choice' && mockEligible !== false` のみを候補にする。`json/mock/mock-config.json` の `practiceChoiceCount` / `extraChoiceCount` / `questionCount` と実Dataが一致しない場合はLoader Errorとする。

保存:

- `ap-study-mock-history-v1`
- `ap-study-mock-active-a-v1`
- `ap-study-mock-active-b-v1`

IPA公式問題の転載・再現とは扱わない。

## 13. 学習進捗Dashboard

Page: `html/progress.html`

Lesson / Practice / Case / Mock履歴を統合し、復習期限・要復習を未着手より優先してNext Actionを提示する。

件数はLesson Index / Practice Manifest / Case Manifestから読み込む。Loader失敗時はSummaryだけでなくUnit Grid、23中分類Table、Next ActionをError Stateへ切り替える。

## 14. Backup / Restore

Page: `html/data.html`  
Runtime: `js/data-tools.js`

### 14.1 Export

`APStudyState.recognizedKeys()` の認識済みlocalStorageのみを書き出す。Backup Schema Versionは `json/project-meta.json` の `storage.backupSchemaVersion` を正本とする。

### 14.2 Import Validation

順序:

1. JSON parse
2. App確認
3. Backup Schema Version確認
4. `storage` object確認
5. 認識済みKey抽出
6. Keyごとの保存形式確認
7. Preview
8. User confirm
9. 現在データの復元前Backup Download
10. commit

壊れた認識済みJSONが1つでも含まれる場合はRestoreを有効化しない。

### 14.3 Safe Preview / Rollback

Import JSON由来の `build` / `exportedAt` 等をraw `innerHTML`へ入れない。DOM Node + `textContent` でPreviewする。

Restore開始前に上書き対象の現在値をMemoryへ退避し、`localStorage.setItem` が途中で失敗した場合は可能な範囲でRollbackする。現在保存データが存在する場合、Restore直前のBackup JSONを自動Downloadする。

今回のPractice問題追加は既存履歴Key / Schemaを変更しない。既存Question IDも変更しない。

## 19. 崩してはいけない仕様

- 既存Term IDを変更・再利用・削除しない。
- 既存localStorage Keyを変更する場合はMigrationを用意する。
- Legacy用語ページを互換層として維持する。
- 通常用語検索入口はGlossaryへ統一する。
- Runtime正本Manifestを分岐させない。
- Buildを複数Runtimeへ手入力しない。
- Import前Validationを外さない。
- Restoreで元データを先に破壊しない。
- 13Unit通常入口はGeneric Unit Hubへ統一する。
- GitHub Pages相対Pathを維持する。
- Secretを公開Repoへ入れない。
- 2026非公開実問題を公開問題として扱わない。
- `118/118`を問題品質・出題Patternの完全Coverageと同義にしない。
- Coverage追加4択をMock対象へ混入させる場合はMock Configとの整合を同時に見直す。

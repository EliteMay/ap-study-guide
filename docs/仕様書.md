# AP Study Notes 仕様書

## 1. 位置付け

応用情報技術者試験（AP）の個人学習用静的Webアプリ。

- 正本: GitHub `EliteMay/ap-study-notes`
- 主利用環境: GitHub Pages
- Build / Project Profile正本: `json/project-meta.json`
- 制作Guide: `EliteMay/web-project-guide`
- Guide採用Version: `json/project-meta.json` に記録
- Project Memory: `PROJECT_LEARNINGS.md`
- 基準: IPA 応用情報技術者試験 シラバス Ver.7.2
- 技術: HTML / CSS / JavaScript / JSON / PDF
- Server必須機能・秘密情報なし

Project Profile: `STATIC + DATA + TOOL + PUBLIC-CONTENT`

## 2. 目的

1. Homeから目的をすぐ選べる。
2. 13Unitから体系的に学ぶ。
3. 構造化Lessonで仕組みを理解する。
4. 短問・長文Case・模試で取り出す。
5. 最新公開公式問題へ接続する。
6. 分からない用語は統合辞書で即時検索する。
7. 進捗Dashboardから弱点へ戻る。
8. 学習データを安全にBackup / Restoreできる。
9. Runtime問題発生時、Local Diagnosticsから原因調査を開始できる。

優先順位: **操作性 → 分かりやすさ → 安定性 → 軽量性 → 保守性 → 見た目**。

## 4. Home

Page: `index.html`  
Runtime: `js/home.js`  
Style: `css/home.css` + `css/home-launch.css`

Homeの第一責務は「行動選択」。詳細Dashboardではない。

主要Action:

- Lesson
- 単語辞書
- 短問
- 長文Case
- 150分模試
- 公式公開問題
- 学習進捗
- 学習データ

`#home-quick-search` は機能名・13Unit名を候補表示し、候補にない語も `html/glossary.html?q=<QUERY>` へ送る。

教材件数はLoader成功後にDataから表示する。初期HTMLは固定件数を持たない。

### 4.1 Home状態

- Loading: 初期表示
- Success: 進捗・Unitを表示
- Empty: Unit Dataが空なら説明を表示
- Error: Loader失敗時に「教材データを読み込めませんでした」と再読込導線を表示

Loader失敗時も主要8Action Cardは利用可能とする。FinderのEvent Listenerは初回だけbindし、学習状態再集計で重複登録しない。

### 4.2 PUBLIC-CONTENT Metadata

Homeは次を持つ。

- `<html lang="ja">`
- 内容が分かる`title`
- `meta description`
- GitHub Pages正式URLの`canonical`

検索流入用Metadataを教材Dataの正本として扱わない。

## 8. 短問総合演習

- Page: `html/practice.html`
- Runtime Manifest: `json/practice/practice-index.json`
- Loader: `js/practice-data.js`
- 履歴: `ap-study-practice-history-v1`
- Choice / Written
- Writtenは最低文字数を満たすまでModel Answerを開けない

### 8.1 Lesson直接Coverage

全118 LessonがPractice Bank内の少なくとも1問から直接参照されることを必須とする。

`json/practice/ap-lesson-coverage-v1.json` は、既存Bankだけでは直接参照されなかったLessonを **1 Lesson = 1問** で補う。Coverageだけを増やす目的で複数Lessonを無関係な1問へまとめない。

現在の短問はManifest集計で139問。UIはこの値を固定表示せずRuntime Dataから算出する。

Coverage追加Bankの4択には `mockEligible:false` を付ける。これは「短問として使わない」という意味ではなく、150分模試の既存科目A Poolへ追加分を自動混入させないための属性である。

## 14. Backup / Restore

Page: `html/data.html`  
Runtime: `js/data-tools.js`

### 14.1 Export

`APStudyState.recognizedKeys()` の認識済みlocalStorageのみを書き出す。Backup Schema Versionは `json/project-meta.json` の `storage.backupSchemaVersion` を正本とする。

Diagnostics Storageは認識済み学習Keyへ含めない。

### 14.2 Import Validation

順序:

1. JSON parse
2. App確認
3. Backup Schema Version確認
4. `storage` object確認
5. 認識済みKey抽出
6. Keyごとの保存形式確認
7. Preview
8. User confirm
9. 現在データの復元前Backup Download
10. commit

壊れた認識済みJSONが1つでも含まれる場合はRestoreを有効化しない。

### 14.3 Safe Preview / Rollback

Import JSON由来の `build` / `exportedAt` 等をraw `innerHTML`へ入れない。DOM Node + `textContent` でPreviewする。

Restore開始前に上書き対象の現在値をMemoryへ退避し、`localStorage.setItem` が途中で失敗した場合は可能な範囲でRollbackする。現在保存データが存在する場合、Restore直前のBackup JSONを自動Downloadする。

### 14.4 Diagnostics接続

- Backup Export: 件数のみBreadcrumb
- Import Validation: success / failureとKey件数
- Restore: success / failureとKey件数
- Storage Failure: Operation + Key種別 + Error概要

ImportしたBackupの本文や学習回答本文はDiagnosticsへ記録しない。

## 15. Development Diagnostics

Core: `js/shell.js`  
View: `html/diagnostics.html`  
View Runtime: `js/diagnostics-view.js`  
Style: `css/diagnostics.css`

Metadata正本: `json/project-meta.json#diagnostics`

### 15.1 目的

ユーザーが毎回「何をしたら壊れたか」を再説明しなくても、直前状態から原因調査できるLocal-first Development Observabilityを提供する。

Analytics / 行動追跡 / 外部Telemetryとして使用しない。

### 15.2 記録対象

- Build / Backup Schema
- Session ID / Session開始時刻
- Current route
- Viewport / Language / Online /最小限のPlatform Summary
- Feature Support
- Initialization result
- JavaScript `error`
- `unhandledrejection`
- non-OK Fetch / Fetch rejection
- Storage read / write failure
- Import / Restore result
- Link / Button等の意味のある操作Breadcrumb

### 15.3 Buffer / Storage

Diagnostics Storage Key: `ap-study-diagnostics-v1`

- Breadcrumb: 最大100
- Error: 最大40
- Network Failure: 最大40
- Initialization: 最大30
- Ring Buffer式に古いものから落とす
- Diagnostic ViewからClear可能
- Diagnostics自身を学習Backupへ含めない

### 15.4 Sanitization / Privacy

記録禁止:

- Password
- API Key / Access Token / Refresh Token
- Authorization Header
- Cookie全文
- 学習回答・記述入力全文
- Backup JSON本文
- File本文
- URL Query / Fragment
- 学習localStorage全dump

Network記録はURL pathnameまでに正規化する。

### 15.5 Diagnostic Export

`html/diagnostics.html` から次を利用可能にする。

- JSON書き出し
- Clipboard Copy
- Clear Diagnostics

ExportはBuild / Route / Environment Summary / Recent Breadcrumb / Error / Network Failure / Storage件数・容量Summaryを含む。学習データ本文を含めない。

## 16. Shared Shell

- `focus-visible`

## 17. Data保存

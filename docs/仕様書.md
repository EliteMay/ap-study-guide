# AP Study Notes 仕様書

この文書は、`EliteMay/ap-study-notes` の**現在の実装状態**を整理するための補助仕様書です。

最上位の方針は `README.md` を参照します。
この仕様書は「今後絶対に変えてはいけない仕様」ではなく、サイトを変更したら実装に合わせて更新します。

---

## 1. 概要

応用情報技術者試験（AP）の学習用静的Webサイトです。

主な用途:

- 用語学習
- 詳細解説
- 検索・カテゴリ絞り込み
- 習得済み管理
- 午後過去問解説
- ランダムテスト
- 今後追加する復習・分析機能

現在はHTML/CSS/JavaScript/JSON/PDFで構成されています。

## 8. 過去問データ

### 現在の保存場所

- 問題文JSON: `json/past-problems/`
- 解説JSON: `json/past/`
- PDF原本: `sources/`
- 一覧索引: `security-past-index.json`

### 現在の参照名

- インデックス → 問題文JSON: `problemFile`
- 解説JSON → 問題文JSON: `sourceProblemFile`

### 設問単位

解説は現在 `sections` で設問単位に管理しています。

主な情報:

- `label`
- `answerTargets`
- `expectedAnswers`
- `answerGuide`
- `why`
- `trap`

問題文JSON側の `targets` と解説側の `answerTargets` が対応している必要があります。

### 将来変更するとき

データ形式を整理し直すことは可能です。
その場合は、既存7問を壊さず一括変換できるようにしてから画面側を変更します。

## 13. GitHub Pages仕様

### 必須

- 入口になるHTMLが公開対象に存在する
- CSS/JS/JSON/PDFへの参照がGitHub Pages上で成立する
- APIキーや秘密情報を置かない

### 現在

- `index.html` はルート
- `.nojekyll` あり
- 静的ファイルのみで動作可能

### パス

リポジトリ名付きURLで動くため、安易なルート絶対パス `/...` は避けます。

例:

```text
../json/...
../sources/...
```

ただし将来ルーティング方式を変える場合は、この制限自体を再検討して構いません。

## 14. 品質チェック

### 現在のツール

`tools/check-json.html`

### 最低限確認すること

#### JSON

- 構文エラー
- ID重複
- terms/details対応
- マニフェスト件数
- 読み込み先ファイル存在

#### 過去問

- `targets` と `answerTargets`
- `expectedAnswers`
- 問題文JSON参照
- PDF参照

#### HTML/JS

- JavaScript構文
- CSS/JSON/PDFパス
- 主要リンク

#### UI

実ブラウザで確認できる場合:

- 主要ボタン
- 検索
- 絞り込み
- 進捗保存
- スマホ幅

確認できない場合は未確認と記録します。

## 16. ChatGPTでの開発

通常作業はChatGPTからGitHubを直接読み書きします。

基本手順:

1. 最新READMEを確認
2. 必要な仕様・作業履歴を確認
3. 対象コードを確認
4. 変更
5. 関連ファイル整合確認
6. 作業報告書更新

Codexは必須ではありません。
実行環境が必要な特殊確認だけ補助として使います。

---

## 17. 現在の完成条件

各作業ごとに以下を満たしたら、その変更は完了扱いです。

- 要求された機能が入っている
- 重大な既知不具合がない
- 関連ファイルが整合している
- データ破損や進捗消失の危険を確認している
- 必要な文書を更新している
- 未確認事項を明記している

サイト全体としては継続開発前提であり、現在の仕様を固定することを完成条件にはしません。

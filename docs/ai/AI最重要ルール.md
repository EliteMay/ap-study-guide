# AI最重要ルール

このファイルは、ChatGPTなどのAIが `EliteMay/ap-study-notes` を扱うときの短い必須ルールです。

## 基本方針

- 正本はGitHubの `EliteMay/ap-study-notes`。
- ChatGPTはGitHub上の最新ファイルを直接確認・編集してよい。
- Codexは通常不要。
- 現在のUI・フォルダ構成・JSON設計は固定仕様ではない。
- より使いやすく、分かりやすく、軽く、保守しやすくなるなら大きく変更してよい。
- ただし、データ破損・進捗消失・参照切れにつながる変更は移行を考慮する。

## 作業前

既存サイトを変更するときは、必要な範囲で次を確認する。

1. `README.md`
2. `docs/仕様書.md`
3. `docs/作業報告書.md`
4. 対象ファイル
5. 関連するHTML/CSS/JS/JSON/マニフェスト

相談や調査だけなら、関係ないファイルまで読む必要はない。

## 優先順位

1. 操作性
2. 分かりやすさ
3. 学習効果
4. 軽量さ
5. 保守しやすさ
6. 見た目

## 変更してよいもの

必要なら次は再設計してよい。

- 画面構成
- UI
- ナビゲーション
- HTML配置
- JavaScript構成
- JSON分割方法
- テスト方式
- 検索方式
- 単元構成
- 学習機能
- README・仕様書

現在の形を守ること自体を目的にしない。

## 慎重に扱うもの

次は複数箇所やユーザーデータに影響するため、変更前に参照先と移行方法を確認する。

- `localStorage` キー
- 用語ID
- 過去問ID
- URLハッシュ
- JSON間参照
- マニフェスト
- PDFと過去問の対応

変更禁止ではない。必要なら移行処理込みで変更する。

## データの基本

現在は次の分離になっている。

- 軽量用語: `json/terms/`
- 詳細解説: `json/details/`
- 過去問問題文: `json/past-problems/`
- 過去問解説: `json/past/`
- PDF原本: `sources/`

大量データをHTML/JSへ直接書き込みすぎない方針は維持する。
より良いデータ構成へ変更する場合は一括整合を取る。

## 解説品質

- 初心者にも分かる言葉を使う。
- 単なる定義ではなく仕組み・具体例・試験での出方までつなげる。
- 汎用テンプレ文を大量に使い回さない。
- 正確性が重要な内容は必要に応じて公式資料などで確認する。
- 未確認内容を断定しない。

## GitHub直接編集

- 変更前に対象ファイルの最新内容を読む。
- 複数ファイルへ影響する場合は関連ファイルも同時に確認する。
- 安全に進められるなら、毎回確認待ちで止めずに作業を完了する。
- 大きな仕様変更でも、ユーザー方針に合っていて影響を把握できるなら実施してよい。
- 変更後は `docs/作業報告書.md` を更新する。
- 実装方針が変わったらREADME・仕様書も更新する。

## 完了前チェック

変更内容に応じて確認する。

### JSON

- 構文
- 件数
- ID
- マニフェスト
- 関連参照

### HTML/CSS/JS

- 構文
- ファイルパス
- リンク
- JSON/PDF参照
- GitHub Pages上の相対パス

### 過去問

- `targets` と `answerTargets`
- `expectedAnswers`
- 問題文JSON
- PDF参照

### 保存データ

- 既存進捗が消えないか
- 形式変更時の移行が必要か

## Codexを使う場合

通常は使わない。

次のように、ChatGPTからGitHubを読むだけでは確認しにくい作業だけ補助として使う。

- Electronビルド
- OS依存処理
- 実機でしか再現しない問題
- 大規模な実行テスト

使う場合も、ChatGPTでできる修正・調査を先に行う。
